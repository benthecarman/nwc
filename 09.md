NWC-09
======

BOLT12 Offers
-------------

`draft` `optional`

## Summary

This specification defines the `make_offer` method for creating a BOLT12 offer through Nostr Wallet Connect.

## Motivation

BOLT12 offers are reusable payment requests. They can have a fixed amount or let the payer choose an amount.

BOLT12 is not supported by all wallets, so offer creation is specified separately from the NWC core protocol.

## Dependencies

Implementations of this specification use [BOLT12](https://github.com/lightning/bolts/blob/master/12-offer-encoding.md) for offer creation and encoding.

## Methods

### `make_offer`

Creates a BOLT12 offer that receives payments into the wallet.

Request:

```yaml
{
    "method": "make_offer",
    "params": {
        "amount": 123, // value in msats, optional; omit or use null for a payer-selected amount
        "description": "string", // offer description, required when amount is set, otherwise optional
        "expiry": 213, // expiry in seconds from the time the offer is created, optional
        "metadata": {} // optional metadata as defined in 06.md
    }
}
```

If `amount` is present, it MUST be a positive integer. If `amount` is absent or null, the offer MUST allow the payer to select the amount.

If `expiry` is present, it MUST be a positive integer. The wallet service MUST encode the resulting expiration time as the BOLT12 `offer_absolute_expiry` field.

Response:

```yaml
{
    "result_type": "make_offer",
    "result": {
        "offer": "lno1..." // encoded BOLT12 offer
    }
}
```

The returned `offer` MUST be a valid BOLT12 offer for the wallet service Bitcoin network. It MUST use the requested amount, description, and expiry.

The wallet service MAY store `metadata` and associate it with payments received through the offer. The `metadata` parameter does not require the wallet service to expose that data in the encoded offer.

Errors:

- `BAD_REQUEST`: A parameter is invalid or the wallet cannot create a valid offer from the parameters.

The wallet service can also return applicable NWC core errors.

## Relationship to other specs

- NWC core defines the request and response envelopes and method discovery.
- [02](02.md) defines the `payment_received` notification that a wallet service can send for payments received through the offer.
- [05](05.md) defines transaction history listing, which can include payments received through the offer.
- [06](06.md) defines the metadata conventions used by the optional `metadata` parameter.
- [321](321.md) defines a method that can return a BIP-321 URI containing a BOLT12 offer.
